# Archive System — Technical Reference

## Architecture

Two components — the archive script and the template modification — work together to preserve every edition as a standalone snapshot.

```
deploy flow (run.sh):

Step 9  → git fetch + git reset --hard origin/main (sync to clean committed state)
          ↓
Step 10 → archive_issue.py saves previous edition (AFTER reset, BEFORE overwrite)
          ↓
Step 11 → copy new HTML/images → git add -A → git commit → git push
```

**Critical ordering rule:** The archive step runs AFTER `git reset --hard origin/main` but BEFORE copying new files. If it ran before the reset, the regenerated `archive/index.html` listing would be reverted by the reset (see pitfall below). The archive step reads the **committed** (previous day's) `index.html`, not the new one.

## archive_issue.py

**Location:** `~/.hermes/profiles/luke/scripts/v2/core/archive_issue.py`

**Usage:**
```bash
python3 archive_issue.py ~/ai-news-deploy
```

**Output JSON:**
```json
{"status": "ok", "archived_to": "~/ai-news-deploy/archive/2026-07-02", "issue_no": 7, "date": "2026-07-02"}
```

Or when nothing to archive (first run, no index.html):
```json
{"status": "nothing_to_archive", "reason": "no index.html"}
```

### Extraction logic

`extract_issue_no()` — reads `No. N` from the masthead via regex `r'No\.\s*(\d+)'`. Returns `None` if not found (graceful fallback — still archives, just without number label in the listing).

`extract_issue_date()` — reads date from `<title>LVX IN TENEBRIS — AI dispatches · July 02, 2026</title>` via regex, parses with `%B %d, %Y`. Falls back to `datetime.now().strftime("%Y-%m-%d")`.

### Paths used

```python
ARCHIVE_URL = "/archive/"  # absolute, works from any page
HOME_URL = "/"              # back link from archive listing
```

Absolute root-relative paths, since the live site is served from the custom
domain root (`luxintenebris.news`), not a GitHub Pages project subpath.
Updated 2026-07-24 when the site moved off `luxintenebris.news/`
onto the custom domain — see [docs/ARCHITETTURA.md](../../../docs/ARCHITETTURA.md#issue-numbering--archiving)
for that migration. If the deploy target ever changes again, update both constants.

## Archive listing page

Generated by `regenerate_archive_index()` in `archive_issue.py`. Lists all directories under `archive/` in reverse chronological order. Each entry shows:
- Date (YYYY-MM-DD)
- Issue number (No. N)
- Full title tag from the archived HTML

The "← Current Issue" link in the archive page uses `HOME_URL` (absolute) so it always returns to the main page.

## Troubleshooting

### Archived page renders unformatted (white background, plain text)
Cause: `style.css` and `fonts/` not copied into the archive directory. Check:
```bash
ls ~/ai-news-deploy/archive/2026-07-02/style.css
ls ~/ai-news-deploy/archive/2026-07-02/fonts/
```
If missing, run the archive script again (it overwrites).

### ◆ Archive link goes to wrong place inside archived pages
Check the archived HTML:
```bash
grep -o 'href="[^"]*archive[^"]*"' ~/ai-news-deploy/archive/2026-07-02/index.html
```
Should show `href="/archive/"` (absolute). If it shows `href="archive/"` (relative), the rewrite failed — re-run the archive script.

### Archive listing missing an edition

**Root cause (most common):** The archive step ran BEFORE `git reset --hard origin/main` in `run.sh`. The regenerated `archive/index.html` was then reverted by the reset. The archive directory was created (untracked, not affected by reset), and since `git add -A` picks up untracked files, only the directory was committed — the listing stayed stale.

**Fix:** Move the archive call to AFTER `git reset --hard origin/main` but BEFORE `git add -A` in the deploy sequence. The regenerated listing then survives into the commit.

**To recover a missing listing entry:** Re-run `archive_issue.py` on the deploy dir:
```bash
cd ~/ai-news-deploy
python3 ~/.hermes/profiles/luke/scripts/v2/core/archive_issue.py .
```
This regenerates `archive/index.html` from all directories on disk. Then `git add -A && git commit -m "fix: regenerate archive listing" && git push`.

### No archive exists for the very first edition
The first run has no `index.html` to archive until after deployment. From the second run onward, the previous day's committed edition is always captured. There's no retroactive archive for issues published before this feature was added (2 July 2026).
